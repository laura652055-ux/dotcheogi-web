# PDF 자료 → 문제 변환

PDF가 준비되면 이 순서로 진행한다.

## 1. PDF 넣기

```
content/정처기-노트.pdf
```

`content/` 는 `.gitignore` 에 걸려 있어서 PDF 원본은 커밋되지 않는다.

**남의 자료(유료 교재, 남이 만든 정리본·문제 모음 등)에서 만든 문항은 공개 저장소에
커밋하지 않는다.** 문장을 바꿔 쓰거나 "~는 무엇인가"로 뒤집어도 그 자료에서 나온
문항이다. PDF 에서 옮긴 문항은 그 PDF 를 직접 만들었을 때만 커밋한다.
([SUBJECT_SCHEMA.md](SUBJECT_SCHEMA.md) 의 '문제의 출처를 밝힐 것')

## 2. 변환 요청

Claude Code에 이렇게 말하면 된다.

> `content/정처기-노트.pdf` 읽고 `docs/QUESTION_SCHEMA.md` 스키마대로
> `src/data/subjects/jeongcheogi/questions.js` 채워줘. 챕터는 3장까지만 먼저.

한 번에 전체를 돌리면 품질이 떨어지니 **챕터 단위로 나눠서** 진행하는 걸 권장한다.

## 3. 변환 시 지켜야 할 것

- **`id` 중복 금지.** `ch08-014` 처럼 챕터+일련번호. 진도/오답 저장 키다.
  나중에 문제를 끼워 넣을 때 기존 id를 밀지 말고 뒤에 붙일 것.
- **`answer` 는 허용 표기를 넉넉히.** 실기는 `제3정규형` / `3NF` / `3정규형`
  전부 정답 처리된다. 약어·풀네임·한글명 다 넣는다.
- **PDF 문장을 그대로 문제로 옮기지 말 것.** "~는 무엇인가"로 뒤집어야
  실제 실기 문제 형태가 된다.
- **`source` 에 출처를 밝힌다.** 해설 아래에 그대로 보이는 값이다. 직접 만든 문항은
  직접 작성, AI 가 만든 문항은 AI 작성이라고 적는다.
  ([SUBJECT_SCHEMA.md](SUBJECT_SCHEMA.md) 의 '문제의 출처를 밝힐 것')
- **코드 실행 결과 문제는 `code` 유형으로.** C/Java/Python 코드를 읽고 출력을
  적는 문제가 실기에서 배점이 크다. 정처기는 **챕터 13(코드 해석)** 이 직접 만든
  코드 문항을 넣는 자리다. 능력단위로는 10장(프로그래밍 언어 활용)이 맞지만, 용어
  암기와 코드 추적은 공부하는 결이 달라서 범위를 따로 고를 수 있게 나눠 두었다.
  이 공개 저장소에는 아직 코드 문항이 없어서 13번 범위가 목록에 보이지 않는다.
- **`code` 유형의 답은 반드시 직접 실행해서 확인한다.** 입력이 있어야 답이 정해지는
  문제는 문제 본문에 입력값을 박아 넣고, 실행 결과가 정의되지 않은 코드(반환값 없는
  함수 등)는 아예 넣지 않는다.
- **음수나 소수점이 답이면 `strict: true` 를 준다.** 기본 채점은 기호를 다 지우기
  때문에 `-8` 과 `8`, `4.0` 과 `40` 을 구분하지 못한다.
- **9장(보안)은 `essay` 유형을 섞는다.** 약술형 대비가 필요하다.

## 4. 변환 후 확인

```bash
npm run dev     # 브라우저에서 실제로 풀어본다
npm run build   # 데이터에 문법 오류 있으면 여기서 걸린다
```

확인할 것:

- 홈의 안내 배너가 지금 문항 구성과 맞는지. 정처기는 빈틈 문제(AI 작성·미검증)
  때문에 `src/data/subjects/jeongcheogi/meta.js` 에서 `isSample` 을 `true` 로 켜 두었다.
  직접 만든 문항을 채워도 배너는 그대로 뜨므로, 문구는 같은 파일의 `sampleLabel` ·
  `sampleNote` 에서 고친다.
- 범위 선택 화면에서 범위별 문제 수가 맞는지
- 답을 일부러 다르게 써 보고 채점이 관대하게 붙는지

## 5. 커밋과 배포

**직접 만든 문항만 커밋한다.** 남의 자료에서 만든 문항이 섞여 있으면 커밋하기 전에
뺀다 (1절).

```bash
git add -A
git commit -m "feat: N장 문제 추가"
git push
```

이 저장소에는 배포 자동화가 들어 있지 않다. 푸시만으로는 사이트가 바뀌지 않으니,
빌드 결과를 올리는 방법은 [README](../README.md) 의 '배포' 항목을 본다.
